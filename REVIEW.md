# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Always returns `{"status": "ok"}` with 200 without checking if MongoDB is reachable. | If MongoDB is stopped, `/health` still returns 200 instead of required 503. | Added `database.command("ping")` inside a try-catch block to raise `HTTPException(503)` if database ping fails or times out. |
| 2 | `compute_late_minutes` (lines 33-38) | Treats UTC datetime as local time when replacing hours/minutes; does not handle timezone conversion to IST; uses `>= 10` boundary instead of strictly `> 10` minutes (600 seconds). | A punch-in at 09:40:00 for a 09:30 shift was calculated as 10 late minutes instead of 0; UTC instants distorted hour math. | Converted datetime explicitly to IST timezone, calculated elapsed seconds, and applied strict `elapsed_seconds > 600` check before flooring to whole minutes from `shift_start`. |
| 3 | `compute_work_hours` (lines 40-42) | Uses Python's built-in `round()`, which implements banker's rounding (round-half-to-even) rather than `ROUND_HALF_UP`. | Floating point values like 4.495 rounded down to 4.49 instead of 4.50. | Replaced with `Decimal.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44-48) | Does not handle overnight shifts where `shift_end <= shift_start`; records overtime for durations < 30 minutes. | Overtime of 15 minutes after shift end returned 15 instead of 0 (violating R3); overnight shift end was assigned to the wrong calendar day. | Added overnight check adding 1 day to `shift_end` when `shift_end <= shift_start`, and enforced minimum 30-minute threshold (`elapsed_seconds >= 1800`). |
| 5 | `create_employee` (lines 78-85) | Relies solely on application-level `find_one` before `insert_one` without handling `DuplicateKeyError` from unique index under concurrent requests. | Two simultaneous `POST /employees` with the same `emp_code` both passed `find_one` and caused an unhandled 500 error on the second insert. | Added unique index `uniq_emp_code` and caught PyMongo `DuplicateKeyError` mapping it to HTTP 409 Conflict. |
| 6 | `create_employee` (lines 78-85) | `created_at` was set using local `datetime.now()` without UTC timezone or millisecond serialization, and the model lacked regex validation for `emp_code`, email, and shift constraints. | `created_at` leaked internal format; invalid `emp_code` like "EMP1" or equal shift start/end were accepted. | Added strict Pydantic `EmployeeCreate` schema and stored timezone-aware UTC datetime truncated to seconds. |
| 7 | `list_employees` (lines 89-96) | Pagination skip calculation was `skip = page * page_size`, which erroneously skipped the first page (`page=1` skipped 20 items). | `GET /employees?page=1&page_size=20` returned items 21-40 instead of 1-20. | Corrected skip calculation to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` (lines 89-96) | `total` count was computed with `count_documents({})`, ignoring the active `department` query filter. | `GET /employees?department=Engineering` returned total of all employees in all departments. | Passed the filtered query dictionary `q` to `count_documents(q)`. |
| 9 | `punch_in` (lines 100-121) | Concurrency race condition: `find_one` check-then-insert allowed duplicate punch-ins for the same employee and date. | Simultaneous punch-in requests created multiple records or raised 500. | Created unique compound index `uniq_emp_code_date` on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 10 | `punch_in` (lines 100-121) | Date was derived from local machine date rather than IST calendar date; overnight shifts before `shift_end` were not mapped to previous day (violating R1). | An overnight punch at 02:00 IST for a 22:00-06:00 shift was assigned to the current day instead of the previous day's shift. | Converted UTC instant to IST and applied overnight rule: if `ts_ist.time() < shift_end`, assigned `record_date = date - 1 day`. |
| 11 | `punch_in` & `list_attendance` (lines 119, 149) | Injected synthetic `"id": str(res.inserted_id)` into response dictionaries. | Contract strictly forbids exposing MongoDB `_id` or synthesizing an `id` field. | Centralized serialization in `serialize_doc()` to remove `_id` and omit any synthetic `id`. |
| 12 | `list_attendance` (lines 125-150) | Loaded the entire matching collection into Python memory (`list(db.attendance_logs.find(q))`) and sorted/paginated in Python. | On ~100k records, endpoint consumed excessive memory and degraded latency. | Moved sorting (`[("date", -1), ("emp_code", 1)]`) and pagination (`skip`/`limit`) into MongoDB query cursor. |
| 13 | `list_attendance` (lines 125-150) | Missing validation for date range where `date_from > date_to`. | Invalid date bounds caused confusing results instead of HTTP 422. | Added validation raising HTTP 422 if `date_from > date_to`. |

### Areas Examined and Found Correct
- **Field Name Consistency:** The core field names across `employees` (`emp_code`, `name`, `email`, `department`, `shift_start`, `shift_end`, `joined_on`) and `attendance_logs` (`emp_code`, `date`, `status`, `punch_in`, `punch_out`, `work_hours`, `late_minutes`, `overtime_minutes`, `half_day`, `history`) match the specification in `DATA_MODEL.md`.
- **Stateless HTTP Design:** The API does not rely on server-side session state or memory caches, adhering to REST conventions.
